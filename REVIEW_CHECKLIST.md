
# Pull Request Review Checklist

## Code Quality
- [ ] Code is readable and follows project conventions.
- [ ] Names are meaningful and consistent.
- [ ] No unnecessary code or duplicate logic.

## Functionality
- [ ] Changes meet the stated requirements.
- [ ] Input validation and business rules are correct.
- [ ] Errors are handled appropriately.

## Security
- [ ] No passwords, API keys, or secrets are committed.
- [ ] Access restrictions are checked where applicable.

## Testing
- [ ] Relevant tests have been added or updated.
- [ ] Tests have been executed and results checked.
- [ ] Existing tests still pass.

## Review Outcome
- [ ] Approved
- [ ] Changes requested
