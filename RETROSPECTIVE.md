# Project Retrospective

## What Went Well

Our team developed a Flask-based Lab Equipment Booking System to manage laboratory equipment and booking requests. We organized the application into routes, models, templates, and tests. GitHub branches, pull requests, peer reviews, and GitHub Actions helped us collaborate and check code quality.

## Challenges

We faced challenges integrating different modules, validating booking times, handling overlapping bookings, and ensuring consistent testing environments. Our local pytest run also encountered an import error, while a recorded GitHub Actions run passed. This showed the importance of checking both local and CI results.

## What We Learned

We gained experience with Flask, database integration, pytest, pytest-cov, Ruff, Git branching, pull requests, peer review, and continuous integration. We also learned that passing one test does not prove that all functional requirements work correctly.

## What We Would Improve

In future, we would write more tests for FR-00 to FR-04, thoroughly test FR-03 booking rules, fix environment issues earlier, coordinate changes to shared files more carefully, and keep documentation and the project board updated.

## Conclusions

This project improved our practical skills in Flask development, automated testing(Ruff Run test), GitHub collaboration, and software quality assurance. Our next priority is to verify all functional requirements, resolve remaining test issues, and maintain accurate project documentation.
